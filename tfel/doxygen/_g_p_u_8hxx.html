Detailed Description

This file declares the primitive of the cuda and hip backends of the generic-parallel interfaces. This file must be compiled by a CUDA or a HIP compiler. The HIP runtime is used if the hip/hip_runtime.h header has been included before this file or if the HIP language is enabled, the CUDA runtime otherwise. Including the HIP runtime header first is required to use HIP on NVIDIA GPUs, since hipcc then calls nvcc.

◆ MFRONT_GENERIC_PARALLEL_GPU_GRID_CONSTANT

#define MFRONT_GENERIC_PARALLEL_GPU_GRID_CONSTANT

qualifier of the function object passed by value to the kernels.

The member functions of this object take its address. nvcc then copies it in the stack of each thread (local memory), unless the parameter is declared __grid_constant__: the threads then read it in place. This qualifier is defined by the headers of CUDA 11.7 or later and requires a compute capability of 7.0 or later. clang reads this parameter in place without it, as do the HIP compilers for AMD GPUs.

apply a function at the points of a batch, one thread per point, and report the statistics of the batch.

The kernel is launched on the stream given by the execution policy. If the computations are asynchronous, this function returns once the kernel is launched. Otherwise, it waits for its completion.

Without statistics given by the calling code, the statistics are held by a block of device memory of a pool of blocks (see StatusBlockPool): no memory is allocated per call. Local statistics are initialized on the host, copied to the block just before the launch and copied back once the computations are completed: the host never accesses the block, which the device may not share with the host while kernels run (devices without concurrent access to managed memory). The device only accesses the block if an event occurs at a point.

If the function never reports an event (see the hasEvents method of the handler), the statistics are neither combined nor reported, and no block of the pool is used.

Template Parameters

PointFunctionfunction applied at the points, which is specific to a generated function

The pool depends on the function applied at the points, whose type is declared in an anonymous namespace by the generated code: each generated function, and thus each generated library, has its own pool. A pool shared by several libraries through the dynamic linker would be destroyed when the library which initialized it is unloaded, even if another library still uses it.
