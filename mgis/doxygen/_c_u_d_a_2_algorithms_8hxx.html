assign the evaluator to a function

implementation of the CUDA assign algorithm

This is the CUDA counterpart of the assign algorithm declared in MGIS/Function/Algorithms.hxx: the values are computed on the graphic card by a CUDA kernel instead of being computed on the host. The evaluator and the function must therefore be callable from the device, which means in particular that they must be built on data accessible from the device, e.g. thrust::universal_vectors, and that the lambda expressions they rely on must be MGIS_HOST_DEVICE lambda expressions.

The spaces of the function and of the evaluator and their number of components are compared and the evaluator is checked before the kernel is launched; the launch strategy itself is described in MGIS/Function/CUDA/Algorithms.ixx.

Only the function arguments which can be captured by a kernel are supported: if the function is not a lightweight view, a view of it is computed on the host and captured by the kernel.

After checking that the spaces of the function and of the evaluator are equivalent, that their numbers of components match and that the evaluator is valid, a device callable lambda expression is built to assign, for a given index, the value computed by the evaluator to that of the function and is applied to every element of the space by cuda::call_kernel.

Two orthogonal choices are made at compile time:

  • if the function is a lightweight view, it is captured directly by the lambda expression, otherwise a view of it is computed on the host and captured,
  • if the value returned by the function can be assigned from that of the evaluator using operator=, a direct assignment is used, otherwise the internals::assign_value helper is used, which handles the cases where the two values have different, but compatible, types.
Note
the requires-clause restricts the algorithm to evaluators defined on a linear element space and to functions defined on the very same space so that a single linear index can address both the function and the evaluator.
