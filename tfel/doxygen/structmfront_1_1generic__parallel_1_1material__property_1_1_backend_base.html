◆ handlesDataTransfer()

virtual bool mfront::generic_parallel::material_property::BackendBase::handlesDataTransfer ( ) const
protectedvirtual

return if the backend shall handle the data transfer from a host to a device

If this method returns true, the array of the pointers to the values of the arguments given by the calling code is named mfront_args_host. The backend shall then define an array of pointers named mfront_args. The pointer to the output values given by the calling code is then named mfront_output_host, and the backend shall define a pointer named mfront_output.

If this method returns false, those variables are directly named mfront_args and mfront_output.

Note
by default, no data transfer is handled

write the beginning of the C function computing the material property on a batch of points (<name>_generic_parallel): signature, error reporting (mfront_report), initialization of the output status and checks of the batch data. The function returns if there is no point. The body of the function is enclosed in a try block, closed by writeCFunctionEnd.

The data of the batch are copied in local variables: mfront_npoints, mfront_output (or mfront_output_host, see handlesDataTransfer), mfront_output_stride, mfront_args (or mfront_args_host), an array of the pointers to the values of the arguments, mfront_strides, the array of their strides, mfront_out_of_bounds_policy and mfront_statuses. The statistics given by the calling code, if any, are mfront_given_statistics, and mfront_deferred_report states if they are given (the output status then only reports the errors of the batch). The execution policy given by the calling code is checked against the policy of the backend (see getExecutionPolicyType): mfront_backend_policy holds the checked policy (null for the default policy), mfront_asynchronous and mfront_preserve_stack_size its common options.

write the body of a kernel, which evaluates the material property at the point mfront_idx. The kernel reads the arguments in mfront_arg0, mfront_arg1, etc. (with the strides mfront_strides if strides are handled) and writes the result in mfront_output (with the stride mfront_output_stride if strides are handled). The parameters are read in mfront_parameters, unless they are treated as static variables.

If the runtime checks are enabled, the evaluation at the point is written in a lambda function returning the status of the point (mfront::gpmp::PointStatus), stored in mfront_point_status. This status is then merged in the statistics mfront_statistics with integer atomic operations, only if an event occurred (see mergesPointStatusesInKernels), or returned by the kernel, to be merged by a reduction.

write the declaration of the statistics mfront_statistics updated by the kernels which merge the statuses of the points with atomic operations.

If the calling code gives statistics (deferred report, required by an asynchronous evaluation), they are initialized by the calling code. Otherwise, they are held by a block of a pool of blocks accessible by the host and by the device (see mfront::generic_parallel::StatusBlockPool), initialized on the host: no memory is allocated per call. The device only accesses the statistics if an event occurs at a point.
