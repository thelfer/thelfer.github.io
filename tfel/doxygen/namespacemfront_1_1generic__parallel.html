Detailed Description

The primitives of the backends (apply, see for instance MFront/GenericParallel/ParallelSTL.hxx) apply a function at the points of a batch. This function returns the statistics of a point (BatchStatistics). The primitives combine them, by atomic operations or by reductions, and report the result through a handler of the statistics given by the interface (mfront::gpmp::StatisticsHandler for the material properties), which provides:

  • the type OutputStatus of the output status and the type Statistics of the statistics updated by the devices and given by the calling code (C structures of the interface);
  • initial(): the statistics of a batch without event, neutral element of the reductions;
  • hasEvents(): false if the function applied at the points never reports an event, in which case the statistics are neither combined nor reported;
  • initialize(Statistics&): initialization of the statistics updated by the devices;
  • report(OutputStatus&, const Statistics&): report of the statistics updated by the devices, once the computations are completed;
  • report(OutputStatus&, Statistics*, const BatchStatistics&): report of the statistics combined by a reduction, or accumulation of those statistics in the statistics given by the calling code, if any.

◆ setMinimalCUDAStackSize()

bool mfront::generic_parallel::setMinimalCUDAStackSize ( const std::size_t stack_size,
const bool preserve = false )
inlinenoexcept

increase the stack size of the threads of the current CUDA device, if the CUDA runtime is loaded by the process. Otherwise, nothing is done. A loaded CUDA runtime does not mean that the computations are performed on an NVIDIA GPU: the primitives of the stlpar and sycl backends only call this function when the computations are offloaded to a GPU (nvc++ -stdpar=gpu, sycl queue running on a GPU).

Some parallel programming models execute the computations on NVIDIA GPUs through the CUDA runtime but give no access to the stack size of the threads: the C++ standard parallelism with nvc++ -stdpar=gpu and SYCL with AdaptiveCpp. The default stack size (1024 bytes) and the automatic increase performed by the CUDA driver at kernel launch, which does not take into account the internal routines of the compilers (such as the division of double precision numbers), are not sufficient for some kernels.

The CUDA runtime is looked up among the loaded libraries, whatever its version, so that this function does not require the CUDA headers nor the CUDA runtime. Nothing is done on systems other than Linux.

Returns
true on success, false if the stack size could not be set or is too small and must be preserved
Parameters
[in]stack_sizeminimal stack size, in bytes
[in]preserveif true, the stack size is only checked
